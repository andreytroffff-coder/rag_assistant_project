# Docker: теория работы и основные концепции

Docker — это платформа для контейнеризации приложений. Она позволяет упаковать приложение со всеми его зависимостями в изолированный контейнер, который можно запустить на любой системе, поддерживающей Docker.

## Что такое контейнеризация?

Контейнер — это легковесная, изолированная среда для запуска приложений. В отличие от виртуальных машин, контейнеры не содержат собственную операционную систему, а используют ядро хостовой ОС, что делает их более быстрыми и экономичными по ресурсам.

Основные преимущества контейнеров:
- **Переносимость** — контейнер работает одинаково на любой платформе (Linux, Windows, macOS).
- **Изоляция** — приложения в разных контейнерах не мешают друг другу.
- **Легковесность** — запуск и остановка контейнеров занимает доли секунды.
- **Масштабируемость** — легко запустить много экземпляров одного контейнера.

## Архитектура Docker

Docker использует клиент-серверную архитектуру:

- **Docker client** (`docker` CLI) — интерфейс, через который пользователь отдаёт команды (например, `docker run`, `docker build`).
- **Docker daemon** (`dockerd`) — фоновый процесс, который управляет контейнерами, образами, сетями и хранилищами.
- **Docker Registry** — хранилище образов (по умолчанию Docker Hub). Можно использовать приватные реестры.

## Базовые объекты Docker

### 1. Образ (Image)
Образ — это неизменяемый шаблон, содержащий всё необходимое для запуска приложения: код, библиотеки, переменные окружения, настройки. Образы строятся слоями (слои кэшируются, что ускоряет пересборку).

### 2. Контейнер (Container)
Контейнер — это запущенный экземпляр образа. Контейнер имеет своё файловое пространство, сетевой стек и изолированный процесс. Контейнер можно остановить, запустить, удалить.

### 3. Сеть (Network)
Docker предоставляет несколько типов сетей:
- `bridge` (по умолчанию) — для изоляции контейнеров внутри одного хоста.
- `host` — контейнер использует сеть хоста напрямую.
- `overlay` — для связи контейнеров на разных хостах (Docker Swarm).

### 4. Хранилище (Volume)
Тома (volumes) позволяют сохранять данные между перезапусками контейнера. Данные хранятся на хосте, но управляются Docker.

## Жизненный цикл контейнера

1. **Создание образа** (из Dockerfile) или скачивание из реестра (`docker pull`).
2. **Создание контейнера** (`docker create`) — выделяется изолированное окружение.
3. **Запуск контейнера** (`docker start`) — запускается процесс внутри контейнера.
4. **Остановка контейнера** (`docker stop`) — процесс завершается.
5. **Удаление контейнера** (`docker rm`) — контейнер и его файловая система удаляются.

Популярная команда `docker run` сочетает `docker create` + `docker start`.

## Dockerfile — инструкции для сборки образа

Пример минимального Dockerfile для Python-приложения:

```dockerfile
# Базовый образ
FROM python:3.11-slim

# Рабочая директория внутри контейнера
WORKDIR /app

# Копируем файлы зависимостей
COPY requirements.txt .

# Устанавливаем зависимости
RUN pip install --no-cache-dir -r requirements.txt

# Копируем остальной код
COPY . .

# Команда по умолчанию при запуске контейнера
CMD ["python", "app.py"]
